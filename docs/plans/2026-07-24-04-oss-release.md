# OSS Release Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement
> this plan task-by-task.

**Goal:** Publish a secure, reproducible, and maintainable first open-source
release of the backup CLI and OCI image.

**Architecture:** Release the same verified source commit to npm and GHCR, attach
provenance and an SBOM, and require the isolated recovery E2E gate before tags
can publish artifacts.

**Tech Stack:** GitHub Actions, npm, GHCR, Sigstore Cosign, Syft, Dependabot,
OpenSSF Scorecard.

### Task 2: Perform backup-specific security review

**Files:**

- Create: `docs/security/threat-model.md`
- Create: `docs/security/credential-matrix.md`
- Create: `test/security/no-secrets.test.ts`
- Modify: `src/logging/redact.ts`

**Step 1: Write the threat model**

Cover:

- Credential leakage through SQL, process arguments, logs, and manifests.
- Malicious backup objects and path traversal.
- Destination lock takeover.
- Restore into the wrong environment.
- Artifact substitution and checksum downgrade.
- Compromised provider credentials.
- Untrusted pre- and post-hooks.

**Step 2: Write failing secret-scanning tests**

Generate representative failures from every adapter and assert secrets are
absent from logs, receipts, manifests, and thrown errors.

Run: `pnpm test test/security/no-secrets.test.ts`

Expected: FAIL for any unredacted adapter path.

**Step 3: Fix redaction at the source**

Do not add test-only masking. Ensure typed secret values cannot be serialized.

Run: `pnpm test test/security/no-secrets.test.ts`

Expected: all generated provider failures remain redacted.

**Step 4: Commit**

```bash
git add docs/security src/logging/redact.ts test/security
git commit -m "security: harden backup credential boundaries"
```

### Task 4: Add signed release automation

**Files:**

- Create: `.github/workflows/release.yml`
- Create: `.github/workflows/scorecard.yml`
- Create: `docs/releasing.md`

**Step 1: Define protected release gates**

A version tag may publish only after:

- `pnpm verify`.
- Container smoke test.
- Recovery E2E.
- Secret scan.
- Vulnerability scan.
- Artifact metadata verification.

**Step 2: Publish from one commit**

Publish the npm package and multi-architecture OCI image from the same tag.
Generate provenance, attach SBOMs, and sign the image with keyless Cosign.

**Step 3: Test a release candidate**

Publish `0.1.0-rc.1` without assigning the npm `latest` tag. Install it in a
clean environment and run the full recovery E2E against the published image.

**Step 4: Commit**

```bash
git add .github/workflows/release.yml .github/workflows/scorecard.yml
git add docs/releasing.md
git commit -m "ci: publish signed backup releases"
```

**Step 2: Publish compatibility evidence**

List tested Langfuse, PostgreSQL, ClickHouse, Redis, MinIO, Node.js, and GCS
versions. Clearly distinguish tested, expected, and unsupported combinations.

**Step 3: Run the release gate**

Expected: all static and unit checks pass.

Expected: the full recovery summary reports pass.

**Step 4: Commit**

```bash

```

## Exit Criteria

- Community, support, governance, and private security-reporting paths exist.
- Threat model and credential matrix cover every adapter.
- npm and OCI artifacts come from one source commit.
- OCI images are signed and include provenance and SBOMs.
- A published release candidate passes the recovery E2E.
- Compatibility claims are backed by exact tested versions.
- Namespace and upstream ownership are not assumed without maintainer approval.
